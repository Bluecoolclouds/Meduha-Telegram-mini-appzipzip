# Фактический расход токеновых моделей: проверка 26 октября 2026

## Решение

**Не включать Ads Studio, Marketing Studio Image 2.5 Flare и Sunburst.**
Формула ставок подтверждена, но источник измерений для окончательного
расхода конкретного запроса не подтверждён. Платная генерация не выполнялась.
Это результат исследования, а не утверждение о невозможности получить эти
данные у Higgsfield.

В приложении сохранена явная блокировка трёх endpoint:

| Название | Каталожный ID | Реальный API endpoint |
| --- | --- | --- |
| Ads Studio | `workflows/ads-studio` | `higgsfield/ads-studio/v1.0` |
| Marketing Studio Image 2.5 Flare | `marketing-studio/image/flare` | тот же |
| Marketing Studio Image 2.5 Sunburst | `marketing-studio/image/sunburst` | тот же |

Для Flare/Sunburst удалены неподтверждённые фиксированные максимумы из
расчётной политики; модели и их схемы остались в каталоге. Блокировка действует
даже при включённом канале, модели и вручную заданной цене. Другие тарифы не
изменялись. Настройки аккаунтов, владельца, spending, каналов, лимитов и
активации моделей не записывались; production не изменялся.

## Проверенные источники

Все перечисленные источники просмотрены 2026-10-26.

1. [Ads Studio: Generate ads](https://docs.higgsfield.ai/docs/models/ads-studio/generate.md),
   разделы Pricing, Usage notes и Check request status:
   шесть ставок; первоначальное списание — оценка, сверяемая после завершения;
   подготовка концепций отдельно не оплачивается; итог batch — сумма расходов
   рендеринга изображений. Приблизительные **$0.084/image** — пример бюджета,
   не фиксированная цена и не максимум. Старый пример $0.1071 также нельзя
   использовать как окончательную цену.
2. [Marketing Studio Flare](https://docs.higgsfield.ai/docs/models/marketing-studio-image/flare.md)
   и [Sunburst](https://docs.higgsfield.ai/docs/models/marketing-studio-image/sunburst.md):
   подтверждают endpoint и ввод, но не определяют контракт финальной стоимости
   или счётчиков. Формула для них получена отдельно из авторизованных смет ниже.
   [Flare Playground](https://open.higgsfield.ai/models/marketing-studio/image/flare/playground)
   и [Sunburst Playground](https://open.higgsfield.ai/models/marketing-studio/image/sunburst/playground)
   содержат рекламные диапазоны, а не измерения расхода конкретного запроса.
3. [Billing and retention](https://docs.higgsfield.ai/docs/concepts/billing-and-retention.md):
   документирует неплатный `POST /estimate/{endpoint}` с теми же параметрами,
   что у генерации, и пример `{ "usd": "0.094" }`. Общее указание использовать
   смету своего аккаунта не превращает описательный ответ токеновой модели
   в числовую или окончательную цену.
4. [Usage and billing](https://docs.higgsfield.ai/docs/enterprise/usage-and-billing.md):
   `GET /models/usage` — агрегаты завершённых генераций по времени/модели,
   при необходимости по API key ID. **Это не billing record**; данные могут
   запаздывать и быть неполными. Для сверки документация направляет к invoices,
   для одного запроса — к status endpoint.
5. [Get request status](https://docs.higgsfield.ai/docs/api-reference/requests/get-request-status.md)
   и [OpenAPI](https://docs.higgsfield.ai/docs/openapi.json):
   `RequestStatus` описывает `status`, `request_id`, `status_url`, `cancel_url`,
   `error`, `images`, `video`, `audio`, `audios`, `expires_at`.
   Счётчики токенов и финальное списание не описаны. Схема не запрещает любые
   дополнительные поля, поэтому это **отсутствие гарантированного контракта**,
   а не доказательство отсутствия данных во всех реальных ответах.
   OpenAPI — дополнительная справка, не полный каталог моделей.
6. [Webhooks](https://docs.higgsfield.ai/docs/how-to/webhooks.md):
   примеры содержат `request_id`, `status`, `error`, `expires_at`, `payload`
   с медиа. Не определены счётчики токенов, финальная стоимость или отдельное
   событие финансовой сверки. Завершение генерации не доказывает финализацию счёта.
7. [Requests](https://docs.higgsfield.ai/docs/concepts/requests.md)
   и [Data retention](https://docs.higgsfield.ai/docs/enterprise/data-retention.md):
   `request_id` нужен для сверки; billing records сохраняются отдельно от медиа.
   Сохранение billing records само по себе не описывает API их чтения.

## Неплатная проверка авторизованного аккаунта

Использован существующий серверный секрет через `Authorization: Key …`;
значение не выводилось и не сохранялось. Только три документированных
`POST /estimate/…` и один `GET /models/usage`; сметы повторно прочитаны один
раз для фиксации содержимого `pricing_description`. Итого **6 смет + 1 GET**.
Ни одного `POST` на endpoint генерации, cancellation, изменения или удаления.
Все ответы — HTTP 200; автоматических повторов не было.

### Сметы

Первое чтение: 20:35:35 UTC. Фиксация описания: 20:35:48 UTC.

Ввод Ads Studio:

```json
{"prompt":"A single blue ceramic cup on a plain white background.","batch_size":1,"aspect_ratio":"1:1"}
```

Ввод Flare и Sunburst:

```json
{"prompt":"A single blue ceramic cup on a plain white background.","quality":"high","moderation":"auto","resolution":"2k","aspect_ratio":"auto","enhance_prompt":false}
```

Все три `/estimate/{endpoint}` вернули одинаковые поля и значения:

```json
{
  "type": "description",
  "pricing_description": "Per 1M tokens: text input $5, cached text input $1.25, text output $10; image input $8, cached image input $2, image output $30. Quality defaults to high. Final cost uses actual token usage and standard credit rounding. The initial charge is an estimate reconciled on completion."
}
```

Поля `usd` нет. Это формула, **не request-level usage, не окончательное
списание, не резерв определённого размера**. Остальные настройки и платные
запуски не проверялись. Результат дополняет, а не переписывает исторический
`reports/pricing-audit-2026-10-26.csv`.

### Аналитика

В 20:35:35.989 UTC выполнен:

```text
GET https://api.higgsfield.ai/models/usage
  ?start=2026-10-01T00:00:00Z
  &end=2026-10-27T00:00:00Z
  &timeframe=day
  &model=higgsfield/ads-studio/v1.0
  &model=marketing-studio/image/flare
  &model=marketing-studio/image/sunburst
  &page=1
  &limit=100
```

Граница `end` — следующая полночь UTC, не утверждение о будущих данных.
Ответ:

```json
{"time_series":[],"total":0,"page":1,"limit":100}
```

Других страниц по этому ответу нет. Пустая аналитика не доказывает отсутствие
расходов за всё время и не позволяет принять usage за ноль. Из ответа нельзя
получить существующий `request_id` для этих моделей. Чужие/случайные ID не
перебирались, новый платный запрос ради появления ID не создавался.

Авторизованный status завершённой генерации этих моделей **не проверен**:
в доступных результатах нет такого ID. Сессии веб-кабинета Higgsfield и
счета с детализацией не предоставлены; API key не считается браузерным входом.
Недокументированные внутренние billing/history endpoint не угадывались.
Таким образом, реально проверен неплатный доступ API key к estimate/analytics,
но не счёт или конечная стоимость генерации.

## Формула и чего не хватает

Для всех трёх моделей подтверждён следующий расчёт **до неуточнённого
провайдерского округления**:

```text
USD = (5 × U_text_in + 1.25 × C_text_in + 10 × T_text_out
     + 8 × U_image_in + 2 × C_image_in + 30 × T_image_out) / 1_000_000
```

Обозначения здесь математические, **не имена JSON-полей провайдера**.
`U` — только некэшированный ввод; `C` — только кэшированный.
Если будущий контракт включает cached во входной total, сначала нужно
вычесть cached из total; повторно оплачивать его как uncached нельзя.
Для Ads Studio batch складываются фактические расходы всех изображений:
агрегированные токены batch нельзя ещё раз умножать на `batch_size`.

Формула без фактических счётчиков не даёт цену. Также не документированы
точная разрядность/порядок «standard credit rounding», финальность данных,
частичный успех batch и момент окончательной финансовой корректировки.

### Источник окончательного расхода и безопасная сверка

* **Сейчас:** документация называет invoices источником финансовой сверки.
  Доступного проверенного API-контракта выдачи окончательной суммы по
  `request_id` не найдено. Aggregate `cost`/`unit_price`, разность баланса,
  рекламные диапазоны и число изображений его не заменяют.
* **Путь A:** получить документированную окончательную сумму с валютой,
  привязкой к аккаунту и `request_id`, признаком финальности и правилами
  корректировок/возвратов. Подтвердить на существующей завершённой операции и
  счёте/реестре, что это final charge, а не начальная оценка.
* **Путь B:** получить документированные измерения всех шести категорий
  токенов (либо однозначные total/cached), их область действия (изображение
  или batch), правила округления и финализации. Проверить расчёт по
  существующей операции против финансовой записи провайдера.
* Отсутствующие/неполные данные должны оставлять расчёт неподтверждённым,
  а не нулевым. Безопасная будущая сверка должна быть идемпотентной по
  аккаунту и `request_id`, учитывать повторные webhook, поздние корректировки
  и частичный результат; тариф, ввод и курс кредитов фиксировать для операции.
* Не списывать с пользователя «фактическую» сумму до появления
  подтверждённых данных. Резерв/финальное списание требуют отдельной
  реализации и проверки лимитов; в этой работе они не внедрялись.

Provider hard cap — дополнительная защита бюджета, **не замена исследованию
usage и не обязательное условие само по себе**. Новый API key, увеличение
лимитов и платный тест сейчас не требуются и не были запрошены.

## Проверка приложения

Добавлены изолированные тесты без генераций и записей в БД:

```text
pnpm --filter @workspace/api-server exec node test.mjs --photo-pricing
pnpm --filter @workspace/api-server run typecheck
```

Проверяются: сохранение моделей в каталоге; блокировка всех трёх моделей
при заданной цене и включённых флагах; отсутствие обращения к провайдеру при
блокировке; отказ от описания/отсутствующей цены вместо нулевого расхода;
неизменность расчёта проверенной Soul Standard.

Результат: **3/3 изолированных теста прошли**, TypeScript — без ошибок,
`git diff --check` — без замечаний. После запуска API дополнительно прочитан
`GET /api/meduha/photo/catalog`: все три модели присутствуют,
`available=false`, причина блокировки относится к неподтверждённой стоимости
конкретного запроса. Главная страница открывается; интерфейс после входа
не проверялся. Интеграционные тесты, меняющие финансовые настройки в БД,
в рамках этой проверки не запускались.
