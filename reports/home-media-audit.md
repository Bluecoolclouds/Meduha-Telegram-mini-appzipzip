# Проверка медиа главной Meduha

Проверены исходный код, размеры HTTP-ответов и кеширование в development
preview, затем мобильный экран 402 × 874. Это не Lighthouse-оценка
и не измерение полной загрузки страницы на мобильной сети.

## Найдено и исправлено

| Медиа | До | После |
| --- | ---: | ---: |
| Маскот hello | 216 535 байт PNG | 10 402 байт WebP |
| Маскот wink | 218 549 байт PNG | 9 790 байт WebP |
| Маскот joy | 219 065 байт PNG | 10 708 байт WebP |
| Нижний маскот curious | 215 145 байт PNG | 9 904 байт WebP, lazy loading |
| Всего эти четыре изображения | 869 294 байт | 40 804 байт, **−95,3%** |

Все состояния `mood()` имеют WebP-варианты, прозрачность и исходные размеры
сохранены. Первый маскот главной получает высокий приоритет; остальные
состояния — низкий, декодирование асинхронное. Исходные PNG не удалены.
Внешний вид и анимация смены настроений сохранены.

Для шести известных `home-*` файлов добавлены ETag и условные ответы 304.
Их размеры берутся из проверенного манифеста фиксированных объектов, без
предварительного запроса метаданных хранилища на каждом запросе.
При замене содержимого нужно согласованно обновлять ID объекта и его размер.
Пользовательские файлы и проверки их доступа этим изменением не затронуты.

HEAD этих файлов в замере после исправления отвечал за 5–42 мс вместо
301–1696 мс до изменения. Это только ответы с заголовками: первоначальная
передача тела по-прежнему зависит от времени доступа к хранилищу и сети.

## Что уже было оптимизировано

- Значок приложения: WebP, **4 032 байта**.
- Карусель фото: WebP, **15 008–58 028 байт** на кадр; заранее загружается
  следующий кадр, а не вся коллекция оригиналов.
- Превью видео карточки: MP4, **646 415 байт**; постер WebP **10 738 байт**.
  `preload="none"`, воспроизведение по видимости; политика отключает autoplay
  для скрытой страницы, reduced motion, Save-Data и медленной 2G-сети.
  При запуске autoplay видимое видео всё равно может начать скачиваться:
  `preload="none"` не означает запрет на загрузку после `play()`.
- Плитки ленты: отдельные WebP-превью с lazy loading и async decoding,
  а не исходные PNG по 1–2 МБ. Проверенные шесть миниатюр — **3 178–42 122 байта**.
  Видео ленты ограничены видимостью, количеством одновременных превью,
  шестью секундами, 480 пикселями, 12 fps и ограниченным битрейтом.

## Подтверждение

- Все 17 проверенных URL вернули HTTP 200.
- Все шесть `home-*` URL с совпадающим ETag вернули HTTP 304 без тела.
- Для видео запрос `bytes=0-1023` вернул HTTP 206 и ровно 1024 байта,
  `Content-Range: bytes 0-1023/646415`.
- Проверки типов frontend/backend и production-сборка frontend прошли.
- Два изолированных теста маршрута прошли, включая все шесть home-файлов:
  HEAD/304 без чтения тела и метаданных хранилища, корректные диапазоны,
  а также прежние проверки публичных примеров.
- Мобильная главная отображается без новых ошибок браузера.

## Оставшееся узкое место

Обновление 2026-10-26: ниже сохранено исходное наблюдение аудита.
Задержка курируемых примеров исправлена отдельным манифестом;
замеры первого и повторного запросов, ограничения и проверки —
в [feed-preview-latency.md](feed-preview-latency.md).

Повторные HEAD шести миниатюр ленты заняли **1668–2079 мс**, несмотря
на небольшой размер файлов. Там остаются обращения к хранилищу и проверки
актуальности. Даже наблюдавшиеся ответы 304 могли занимать около двух секунд.
Это отдельная задержка сервера, которую уменьшение картинок само по себе
не устраняет.

Для дальнейшего ускорения следует отдельно подготовить быструю отдачу
курируемых публичных примеров. Оптимизации пользовательских публикаций
обязаны сохранять немедленную проверку снятия с публикации и доступа:
нельзя делать их общедоступными или кешировать разрешение ради скорости.

Изменения проверены в preview. Публикация в production в рамках этой
проверки не выполнялась; настройки генераций, расходов и владельца не менялись.

## Быстрый регрессионный контроль

`pnpm --filter @workspace/meduha run test:home-media` — отдельная локальная
проверка на стандартном `node:test`, также включённая в обычный frontend `test`
и зарегистрированная как validation `home-media`.

| Объект | Максимум, байт |
| --- | ---: |
| Каждый обычный Mood WebP | 16 000 |
| Glossy WebP (отдельная крупная иллюстрация, не на главной) | 180 000 |
| Четыре маскота главной вместе | 50 000 |
| Логотип WebP | 6 000 |
| Каждое home-фото | 70 000 |
| Четыре home-фото вместе | 180 000 |
| Постер home-видео | 16 000 |
| Home-видео | 800 000 |

Пороги оставляют небольшой запас относительно замеров выше, но не допускают
возврата к тяжёлым оригиналам. Это размеры файлов, **не финансовые лимиты**.
Для локальных изображений проверяются реальные байты, заголовок WebP и размер
RIFF; для всех значений типа `Mood` — связь с WebP и существенное уменьшение
относительно исходного PNG.

Для шести storage-backed home-файлов проверяются **объявленные размеры**
и MIME-типы из локального `motionAssets`, а не содержимое хранилища.
Сеть намеренно не используется: при замене объекта необходимо по-прежнему
согласованно обновлять ID и фактический размер в манифесте. Проверка не может
доказать соответствие удалённых байтов манифесту.

Тесты читают TypeScript/JSX через TypeScript AST и исполняют только выделенные
функции с локальными подставными hooks/элементами: приоритет первого маскота,
lazy/async нижнего, отсутствие PNG на главной, отсутствие безусловного
`src`/`autoplay` у home-видео, все сочетания видимости/активности/разрешения
автопроигрывания и освобождение источника при остановке. Отдельно проверяются
reduced motion, Save-Data, 2G и условное подключение preview-видео в плитках
ленты вместо оригинала.

Это контроль контрактов компонентов, а не измерение браузерного трафика.
Он не запускает сервер, базу, Telegram, owner designation, генерации или
финансовые операции. Имеющиеся HTTP range/304 тесты не дублируются.
